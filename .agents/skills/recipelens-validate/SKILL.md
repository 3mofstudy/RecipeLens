# RecipeLens 食譜轉換驗證

提供可核對的結果，指出最後成功階段、失敗原因與保留檔案。先遵守根目錄 `AGENTS.md`；本流程不授予額外下載、AI 呼叫或雲端上傳的權限。

## 選擇驗證範圍

- 只有程式變更或要求跑測試：執行相關離線測試，不自行下載影片或呼叫真實 AI。
- 已有本機食譜：先檢查指定產物，能以現有資料確認的問題不必重新轉換。
- 要求實測網址或重現轉換：使用指定網址與平台、字幕、AI 選項；非必要選項沿用現有設定並說明，不隨意換影片或 AI 平台。
- 要求真實雲端驗證：確認授權涵蓋本次檔案、格式、名稱及目的地。未涵蓋時先完成本機可驗證部分；另一份食譜的授權不自動延伸到本次。

## 定位失敗階段

先讀錯誤與處理紀錄，區分資訊欄、影片下載、字幕／語音、AI、Markdown／截圖、PDF／DOCX、Google Drive。`model_not_found` 不等於影片下載失敗；已產生 MD 但 PDF 失敗屬部分成功。

只讀相關程式：下載看 `src/environment.py`、`src/video_download.py` 與平台下載器；字幕與 AI 看 `src/media.py`、`src/ai_recipe.py`、`src/recipe_lens.py`；文件看 `src/recipe_export.py`、`src/document_export.py`；介面與上傳看 `src/gui.py`、`src/qt_window.py`、`src/cloud_upload.py`、`src/qt_drive_dialog.py`。

## 離線測試

從專案根目錄執行；小範圍修正可先跑相關測試模組。

```powershell
rtk proxy uv run --locked --extra transcription python -m unittest discover -s tests -p "test_*.py" -v
```

GUI 測試沿用 `tests/qt_support.py`，不登入真實 Google 或 AI 帳號。本機 HTTP 測試需要回環連線，被沙箱阻擋時區分環境限制與功能失敗。記錄摘要與程序結束代碼；摘要為 OK 但程序異常結束時，先查明原因，不只報全部通過。

## 真實影片實測

先檢查 `main.py --help`、實際工具路徑及版本。保持使用者指定的輸出位置；未指定時使用獨立本機驗證輸出根目錄，避免混淆舊產物。不要刪除舊食譜來騰出名稱。

CLI 不執行雲端上傳，可先隔離本機問題。以下是範本，執行前替換網址與輸出路徑，其他參數依本次選項加入：

```powershell
rtk proxy uv run --locked --extra transcription python main.py "<公開影片網址>" --output "<本機驗證輸出根目錄>" --subtitle-mode original
```

只有需要驗證 GUI 整合時才操作 GUI，先檢查快取是否會觸發自動上傳；不要為本機測試更改使用者的永久設定。

- HTTP 403／runtime 警告：核對 PATH 舊 yt-dlp 是否遮蔽 uv 版本，以及 JavaScript runtime 路徑；不以讀取瀏覽器 cookies 作為預設修復。
- 模型不支援：「自動」可能沿用 CLI 全域設定。核對實際模型與帳號回應，保留錯誤；不假設固定模型永遠可用，不擅改全域設定。
- 字幕缺失：核對平台字幕、內嵌字幕與語音轉錄的實際路徑，不要求手動上傳字幕來通過測試。
- 修正有證據的原因後才重試；相同原因持續失敗時停止盲目重試，保留紀錄並說明尚缺條件。

## 本機產物檢查

以本次回傳的 Markdown 路徑定位結果，不靠資料夾時間猜測。

1. 同層同名 MD、PDF、DOCX 都存在且非空白，並有本次引用截圖；缺漏時回報部分成功。
2. 讀取 UTF-8 Markdown，核對來源網址、食譜內容、繁體中文整理、未說明／待確認用量及要求的字幕全文。檔名正確不等於內容正確。
3. 用 Markdown parser 取得圖片引用，可重用 `src.document_export.recipe_blocks`；解析後核對檔案存在、可解碼且未越出本次食譜資料夾，不載入遠端圖片。
4. 區分 AI 步驟截圖與資訊欄直接保留的參考畫面。後者是均勻取樣，不宣稱已逐步配對，不硬性要求圖片數等於步驟數。
5. DOCX 能開啟且含食譜文字與嵌入圖片，PDF 能開啟並顯示中文。需驗證排版時再檢視或渲染頁面，查缺字、截斷、圖片比例；檔頭或 ZIP 檢查不能證明視覺正確。
6. 涉及 GUI 時，核對本次文字與圖片預覽、文件按鈕的路徑，以及錯誤或取消後本機檔案仍存在。
7. 每一個.py 檔案都應有對應在 readme.md 註釋。

## 雲端與交付

本次範圍包含真實上傳時，才核對實際目的地、格式、檔名及 MD 圖片資料夾。使用既有重試機制，不反覆建立副本或自行刪除測試檔；需要使用者登入時先保留本機結果。

以繁體中文簡短回報驗證層級、測試或指定影片、最後成功階段、文件與截圖數、可點選的本機絕對路徑，以及未驗證或失敗項目。真實上傳成功才附雲端連結；僅通過模擬上傳測試必須明確註明。
